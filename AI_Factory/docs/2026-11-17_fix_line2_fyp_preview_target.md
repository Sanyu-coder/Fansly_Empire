# 第2ライン（Fansly予約ボット）FYP無料プレビュー添付先修正レポート

## 1. 概要・日付・対象ファイル
- **日付**: 2026-11-17
- **対象ファイル**:
  - `factory_line2.py`
  - `docs/2026-11-17_fix_line2_fyp_preview_target.md`

## 2. 背景・解決したかった課題（Before）
第2ライン（`factory_line2.py`）を実行して Fansly へ本編メディア群（本編動画 1本 ＋ 採用画像 N枚）を一括アップロードした後、Fansly のメディアモーダル上で本編動画に対して「+ Add free preview（+ 無料プレビューを追加）」→「Upload」で FYP 用動画を添付する仕様となっていた。

しかし、以下の問題により本編動画ではなく末尾の画像ファイルに対して無料プレビューが添付されてしまう事象が発生していた：
1. 一括アップロード直後はモーダル内で一番最後にアップロードされた「画像」が初期選択状態になっていた。
2. `select_target_media_in_modal` でサムネイルをクリックして動画に切り替える際、完全一致ファイル名のみを検証していたため、UI上の表示省略やタイムラグによって一致判定がスルーされるケースがあった。
3. 一番致命的だった点として、`attach_free_preview` 内で `select_target_media_in_modal` の戻り値（成功/失敗）を評価せず、切り替えに失敗した場合でも後続のプレビュー添付処理をそのまま実行していたため、初期選択されていた画像ファイルに対して FYP プレビュー動画がアップロード・添付されてしまっていた。

## 3. 採用した設計方針・理由（Why / ADR）
1. **本編動画の確実なフォーカスと判定多重化**:
   - 一括アップロードの順序は常に `[main_video] + images` と定義されており、動画は必ず先頭（index 0）に位置する。
   - 下部サムネイル候補のうち、動画固有アイコン（`fa-play`, `fa-video`, `app-video-thumbnail`, `video` タグ）を持つ要素を最優先で特定・クリックする。
   - サムネイル全体も画面座標（左から右）でソートし、先頭要素を確実にアクティブ化する。
   - 判定ロジックもファイル名完全一致だけでなく、拡張子なし語幹（stem）やプレビューコンテナ内の `video` タグ実在の多重チェックを行う。
2. **安全ガードの導入（Fail-Safe）**:
   - `select_target_media_in_modal` が `False`（動画選択確認不可）を返した場合は、画像ファイルへの誤添付を絶対に防ぐため、後続の「+ Add free preview」をクリックせず即座にエラー中断（`False` 返却）するフェイルセーフを設けた。

## 4. 実装内容・変更点サマリ（After）
- `select_target_media_in_modal(page, target_filename)`:
  - 判定ヘルパー `is_target_selected()` を新設（完全一致、stem一致、プレビュー枠内 `video` タグ存在）。
  - 動画インジケータ（`fa-play`, `fa-video` 等）を持つサムネイルを優先クリック。
  - 下部サムネイルバーの座標ソートにより先頭（動画）を優先クリック。
  - 切り替え確認成功時のみ `True` を返すよう厳密化。
- `attach_free_preview(page, target_media_filename, fyp_preview_path)`:
  - `selected = select_target_media_in_modal(page, target_media_filename)` の結果をチェックし、`not selected` の場合は警告ログを出力して直ちに `return False` する安全ガードを追加。

## 5. 作業中に発生した問題・ハマりポイントと解決策（Troubleshooting）
- **問題**: Fansly のメディアモーダルでは、動画サムネイルのプレビュー枠表示に若干のデコード・レンダリング遅延が発生することがある。
- **解決策**: サムネイルクリック後に `time.sleep(0.5)` の待機を設け、UIへの反映を確実に待ってから多重判定を行うように調整。また、動画選択失敗時に無理に処理を継続させず、画像への誤添付を未然に防止する設計とした。

## 6. 今後の注意点・残タスク
- Fansly 側の UI アップデートによりモーダル内のクラス名やアイコン構成が変更された場合でも、座標基準（先頭インデックス・左端フォールバック）と動画タグ判定がセーフティネットとして機能する。
- 実機での次回予約投稿実行時に、ログに `✔ サムネイル一覧（#1）から対象メディア [...] を選択切り替え完了！` または `✔ 動画インジケータ付きサムネイルから対象メディア [...] を選択切り替え完了！` と出力され、本編動画に正しくプレビュー動画が紐付くことを確認する。
