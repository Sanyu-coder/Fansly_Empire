## 1. 背景・解決したかった課題（Before）

従来のシステム（v2系）では機能追加を重ねた結果、運用面・システム面の双方で以下のボトルネックが発生していた。

1. **コンソール画面の「行ったり来たり（二度手間）」**:
   - 未選別フォルダ（`01_candidates`）を開いて動画キューに登録したあと、動画バッチ完了後に**もう一度同じフォルダを開き直して**画像採用・モザイク・動画モザイクを行う必要があった。
   - 複数タブ（Step 1〜4）に同じ案件が重複表示され、「今どの案件に何の作業が必要か」が直感的に分かりづらかった。
2. **モザイク作業の二重の手間と規約リスク**:
   - Fanslyの「有料サブスク本編（日本の法規制準拠：陰部のみモザイク・乳首解禁）」と「無料プレビュー/FYP（Fansly規約準拠：陰部＋乳首の両方にモザイク）」で別々の動画モザイク作業を2回行う必要があり、作業負担とモザイク漏れリスクが高かった。
3. **投稿パターンの分岐過多による不安定さ**:
   - 「画像のみ投稿（Fansly標準 Blurred copy 分岐）」「動画先行確定の `video_lock` 制御」など条件分岐が多く、第2ライン（`factory_line2.py`）での予約投稿時にエッジケースによるスキップやエラーが発生しやすかった。
4. **スケジュール枠・キャプションの運用課題**:
   - スケジュール時刻が固定プリセットに縛られており、`03_posted` 済みの予約日時を参照していなかったため重複予約のリスクがあった。また、毎回6候補のキャプションから手動で選ぶ手間がかかっていた。

## 2. 採用した設計方針と核心仕様（Why / ADR）

### ① 全投稿「動画必須（動画1本＋採用画像0〜N枚）」による完全1本道化
- **判断理由**: 画像のみの投稿パターンや `Blurred copy` への分岐、動画未完時の先行確定（`video_lock`）をすべて廃止。すべての投稿を「動画1本＋採用画像0〜N枚」に統一することで、UI操作・データ構造・第2ラインの自動予約フローを一貫した固定1パターンに単純化した。

### ② 直線コンベア型パイプライン（1案件＝今やるべき1工程のみ表示）
- **判断理由**: `post_data.json` の `stage`（`"step1"` | `"step2"`）およびフォルダ移動（`01_candidates` → `02_ready_to_post` → `03_posted`）により、完了ボタンを押した瞬間に現在の画面一覧から即座に消え、次工程へ進む構造を採用。作業の重複や見落としをゼロにした。

### ③ 2レイヤーAIモザイクの1回操作統合（3パターン自動判定）
- **判断理由**: Step 2 の動画モザイクエディタ上で **🔴赤枠（`GENITALIA` / 陰部：本編＆FYP両方）** と **🟡黄枠（`BREAST_EXPOSED` / 乳首：FYPのみ）** を1画面で同時指定し、1クリックの1パス走査で本編用（`*_MOSAIC.mp4`）とFYP用（`*_FYP_PREVIEW.mp4`）を同時出力（または無修正維持）できるようにした。

## 4. 途中に発生した技術課題と解決策（Troubleshooting）

1. **別プロセス起動によるキャプション長短ローテーション途切れ問題（Phase 1）**
   - **原因**: `worker_service.py` が1セットごとに `subprocess.Popen` で `factory_line1.py` を別プロセス起動するため、メモリ上の変数では交互切り替えが維持できない。
   - **解決策**: 直近フォルダの `post_data.json` と `logs/caption_rotation.json`（フォールバックとしてフォルダ連番の偶奇）を参照して反転させる永続ステート方式で解決。
2. **陰部のみモザイク（赤枠あり・黄枠なし）ケースの整合（Phase 2）**
   - **原因**: 胸は着衣だが陰部のみ露出している動画では、本編とFYPで同じ赤枠モザイク動画が必要になる。
   - **解決策**: 1回エンコードした `*_MOSAIC.mp4` を `*_FYP_PREVIEW.mp4` へコピー配置し、`mosaic_mode: "both"` として扱うことで下流のUI・第2ラインの分岐をゼロにした。
3. **`03_posted` の予約済み枠未参照による重複予約リスク（Phase 3）**
   - **解決策**: 空き枠計算関数 `collect_existing_scheduled_times()` の走査対象に `02_ready_to_post` だけでなく `03_posted` 配下の全アーカイブフォルダを追加。
4. **パターン③（完全健全動画）での本編動画除外バグ（Phase 5）**
   - **原因**: 旧コードに `if p != fyp_preview_path:` の除外条件があり、`main_video` と `fyp_preview_video` が同一ファイル名（`video_output.mp4`）の場合に本編動画リストが空になる問題があった。
   - **解決策**: 同一ファイル名であっても本編メディア群（`[main_video] + images`）と無料プレビュー専用アップロードの双方で独立してアップロードするよう修正。
