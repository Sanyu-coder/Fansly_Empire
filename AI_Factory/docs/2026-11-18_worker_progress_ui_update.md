# ワーカー進捗UIの刷新 - 2段階プログレスバー表示

## 概要・日付・対象ファイル

- **タスク実施日**: 2026年11月18日
- **対象ファイル**:
  - `@app/services/worker_service.py`
  - `@app/routes/worker_routes.py` 
  - `@app/templates/index.html`

## 背景・解決したかった課題（Before）

- 既存のワーカー進捗表示はコマンドプロンプト風のテキストログのみで、視覚的な進捗状況が把握しづらかった
- ユーザーが作業の進行状況を一目で確認できないため、運用の透明性が低かった

## 採用した設計方針・理由（Why / ADR）

- 2段階の進捗表示方式を採用：
  - **全体進捗バッジ**: 何件中何件が完了したかを即時把握可能
  - **個別プログレスバー**: 現在処理中の1件の進行度を視覚的に確認可能
- フロントエンドとバックエンドの連携構造を明確にし、リアルタイム進捗更新を実現
- 既存のワーカー停止・自動リロード機能は維持

## 実装内容・変更点サマリ（After）

### バックエンド側 (`worker_service.py`)
1. `worker_state`構造体に進捗フィールドを追加：
   - `total_items`: 全体の処理予定件数
   - `completed_items`: 完了した件数  
   - `item_progress`: 現在処理中の1件の進捗率（0〜100）
   - `current_stage`: 現在の工程を表す短い日本語ラベル

2. 各ワーカー関数を修正し、リアルタイムで進捗情報を更新：
   - **第1ライン**: 各iterationの進捗をComfyUIステップに応じて更新
   - **動画バッチ**: フォルダ数を事前カウントし、各処理完了時に進捗を更新
   - **第2ライン**: 予約待ち件数を事前カウントし、各投稿完了時に進捗を更新

### フロントエンド側 (`index.html`)
1. 画面下部の`#log-drawer`要素を2段階進捗UIに刷新：
   - 全体進捗バッジ：例「全体進捗: 1 / 10 件完了 (10%)」
   - 現在処理中の1件の横長プログレスバー（アニメーション付き）
   - 現在のフェーズ名表示：例「画像生成中 (ComfyUI)...」
   - 詳細ログの折りたたみ機能を保持

2. JavaScriptによるリアルタイム進捗更新ロジックを追加：
   - `worker_status` APIを定期的にポーリングしてリアルタイム更新
   - プログレスバーのアニメーション効果を実装

## 作業中に発生した問題・ハマりポイントと解決策（Troubleshooting）

1. **ファイル末尾のスタイルシート追加で文字列検索に失敗**:
   - 問題: HTMLファイル末尾の位置を正しく特定できず、スタイルシートの追加に失敗
   - 解決策: 手動で位置を特定して追加

2. **プログレスバーのアニメーション効果の実装方法検討**:
   - 問題: CSSのtransitionプロパティを使用してスムーズなアニメーションを実現
   - 解決策: `transition: width 0.3s ease`でスムーズな進行アニメーション実装

## 今後の注意点・残タスク

- プログレスバーの表示領域は適切に調整し、情報の可読性を維持
