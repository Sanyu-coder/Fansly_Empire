# 全アプリ共通：タスク完了時の自動ドキュメント作成ルール（必須）

`C:\Fansly_Empire` 配下のいずれのアプリケーション（`AI_Factory`、`AI_DM_Sales`、`AI_Analytics_Console` 等）であっても、コードの実装・修正・バグ対応などの開発タスクを完了し、ユーザーへ最終の完了報告を行う**直前**に、毎回必ず以下の2つを自動で実行すること（ユーザーからの都度の指示を待たずに実行すること）。

## 1. 振り返り・設計判断レポートの自動作成（`<対象アプリ>/docs/`）
- 今回作業を行った対象アプリのフォルダ配下にある `<対象アプリ>/docs/YYYY-MM-DD_<変更内容を表す短い英語スネークケース>.md` を新規作成（同日の連続フェーズであれば同ファイルへ追記）し、以下の6項目を日本語で漏れなく記載すること：
  1. **概要・日付・対象ファイル**
  2. **背景・解決したかった課題（Before）**
  3. **採用した設計方針・理由（Why / ADR）**
  4. **実装内容・変更点サマリ（After）**
  5. **作業中に発生した問題・ハマりポイントと解決策（Troubleshooting）**
  6. **今後の注意点・残タスク**

## 2. 対象アプリのプロジェクト地図（`PROJECT_MAP.md`）の自動更新
- 新規ファイルの追加、関数・APIの追加や削除、ファイル間の役割変更を行った場合は、**作業を行った対象アプリの直下にある `<対象アプリ>/PROJECT_MAP.md`** も必ず最新状態に更新すること。

## 3. 人間用運用マニュアル（`docs/USER_MANUAL.md`）の自動更新ルール
- 新機能の追加、管理画面（UI）のボタン・タブ・設定項目の変更、または新しいエラー対処法・運用手順が発生したタスクでは、完了報告の直前に **`docs/USER_MANUAL.md`** も必ず最新状態に更新すること。
- 更新時は既存の目次構成・トラブルシューティング表・逆引きスタイルを維持し、作業する人間が迷わず操作できるよう具体的に記載すること（内部コードのリファクタリングのみで操作方法が変わらない場合は更新不要）。

## 完了報告の条件
- 上記のドキュメント作成・更新が完了するまで、ユーザーに「タスク完了」を宣言しないこと。
